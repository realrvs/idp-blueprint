# Contributing

## Процесс изменений

1. Создайте ветку: `git checkout -b docs/<краткое-описание>`.
2. Внесите изменения.
3. Если изменение архитектурное — добавьте ADR в `docs/adr/`.
4. Откройте PR с описанием: **что**, **почему**, **ссылка на ADR** (если есть).
5. Дождитесь ревью от Platform Team и (для security-related) Security Champion.

## Стиль

- Markdown, один язык на документ.
- Mermaid-диаграммы inline в Markdown.
- Ссылки на ADR — через относительные пути.

## ADR

Каждое ключевое решение оформляется как ADR в формате MADR.
Шаблон: `docs/adr/0000-template.md`.
Нумерация: `NNNN-краткое-название.md`, где `NNNN` — четырехзначный номер.

**Заполнение полей:**
ADR заполняется автором при создании (дата создания, авторы).
Поля «Дата утверждения» и «Авторы» (если менялись) обновляются при переводе
статуса `Proposed → Accepted` архитектурным комитетом. До этого момента
плейсхолдеры (`YYYY-MM-DD`, `<имена>`) — ожидаемое состояние, а не ошибка.
