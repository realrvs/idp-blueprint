# ADR-0006: Выбор Git-провайдера и CI-движка

- Статус: Proposed
- Дата: 2026-10-27
- Авторы: Platform Team
- Контекст blueprint: docs/blueprint.md

## Контекст и проблема

Архитектуре (Слой 3: Доставка) требуется источник правды для GitOps и CI-движок для сборки артефактов. Требуется решение, которое может работать в закрытом контуре (on-premise) и соответствовать требованиям по локализации данных.

## Рассмотренные варианты

1. **GitLab / GitHub (SaaS или Self-hosted) + внешний CI** — классический выбор, но может не подходить по требованиям импортозамещения или политикам безопасности.
2. **GitVerse** — интегрированное решение (Git + CI/CD + AI-ассистент GigaCode), поддерживающее развертывание on-premise и имеющее официальный MCP-сервер.

## Решение

Архитектура не привязана к конкретному провайдеру. Для реализации в контуре с требованиями импортозамещения/локализации выбирается **GitVerse**. Для остальных случаев — GitLab/GitHub.

## Последствия

### Положительные
- **Единая среда**: GitVerse объединяет хостинг репозиториев, CI/CD и AI-ассистента.
- **Интеграция с AI (Слой 5)**: Наличие GitVerse MCP Server позволяет агенту получать актуальные данные о статусах CI/CD и управлять PR.
- **Независимость слоев**: ArgoCD и Crossplane работают с Git по стандартным протоколам, поэтому выбор провайдера не влияет на Слои 2 и 3.

### Отрицательные
- При смене провайдера потребуется миграция репозиториев и настройка CI/CD.
- Ограниченная экосистема плагинов по сравнению с GitHub/GitLab (на текущий момент).

## Критерий пересмотра

- Появление критических ограничений в GitVerse, блокирующих работу платформы.
- Изменение требований безопасности или политик импортозамещения.
