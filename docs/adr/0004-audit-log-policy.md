# ADR-0004: Политика аудит-логов агентской цепочки

- **Статус:** Proposed
- **Дата:** YYYY-MM-DD
- **Авторы:** <имена>
- **Контекст blueprint:** [docs/blueprint.md](../blueprint.md)

## Контекст и проблема
Аудит должен отвечать на вопрос «кто, что, когда» для каждого tool-call,
но не хранить PII/секреты, которые могут попасть в параметры.

## Рассмотренные варианты
1. **Полное логирование** — риск утечки PII/секретов.
2. **Логирование + маскирование** — детекция PII/секретов (regex + entropy),
   хэширование совпадений перед записью.
3. **Только метаданные** — недостаточно для разбора инцидентов.

## Решение
Вариант 2: логирование с маскированием. Срок хранения — <N> дней.
Доступ к аудит-логам — только Security и Platform Team.

## Последствия
### Положительные
- Compliance (SOC2, GDPR).
- Материал для разбора инцидентов.

### Отрицательные
- Дополнительная нагрузка на запись (детекция + хэширование).
- Риск ложных срабатываний детектора PII.

## Критерий пересмотра
- Изменение регуляторных требований.
- Появление новых классов чувствительных данных.
